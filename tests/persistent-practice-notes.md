# Persistent practice and source-grounded coach

Sources inspected: local pinned PMP-N/SOMU, PMP/Neon and alsaeed-pmp2026 reference HTML/JSON under the prior source audit. SOMU removes a wrong ID on correct retry and re-adds on wrong retry; its state is browser-local. Neon custom practice filters real approach/domain/chapter and bounds its count. Neon GOLDEN unions wrong and flag IDs; that behavior is deliberately not imported because the user requested chosen favorites only. Anonymous localStorage histories/favorites are never assigned to a logged-in account.

Current implementation derives remaining mistakes from each account/package's saved per-question attempt outcomes in chronological order. Old attempts without per-question details cannot be reconstructed and are disclosed, not invented. Correct retry resolves only that question, and later wrong attempts re-add it. Stable attempt keys deduplicate network retries without rewriting past scores/history. Favorite CAS rows are additive, owner/package scoped and quality-gated. Custom practice uses actual bank facets, unique IDs, language readiness and counts from 1 to min(180, available).

Coach root cause: the live exam-ai-v19.js capturing interceptor used one hardcoded example per course plus generic elimination rules, overriding the unified engine handler. It now uses current engine question, authored selected-language rationale, reordered option feedback and explicit authored examples only. None of the three source schemas contained a consistent standalone per-question practical-example field. Missing examples/hints are clearly disclosed; no generic example is presented as bespoke. No external AI or new provider, no answer-key inference, no account/question cache. Disabled coach in graded mocks remains blocked. Tests execute actual UnifiedExam and the live interceptor together.

Migration: adds learner_question_favorites only; existing attempts/progress/question records are neither removed nor rewritten. Runtime packaging includes the module. No production DB was touched. Real gateway HTTP acceptance is pending independent runtime verification because the current Node24 native SQLite addon aborts during gateway startup; synthetic SQLite API and DOM suites pass separately.
